# #771 — Diagnóstico de conciliación de página operativa

Los endpoints canónicos existentes `GET /reports/operational/{sales,purchases}` ya calculan sumarios desde `SalesInvoice` y `PurchaseInvoice` con transacción RepeatableRead por tenant. Ahora añaden `drillDownReconciliation` en ambas respuestas: `NOT_COMPLETE` cuando se solicita una página parcial (`hasMore` o `skip>0`); `MATCH` **solo** si se han leído todos los documentos y las cantidades exactas agrupadas por moneda/estado coinciden con la suma original; `MISMATCH` ante diferencias detectadas. Opera en cadenas con BigInt a seis decimales, sin FX ni floats. Cuenta documentos y rechaza duplicados/grupos inesperados. Es un diagnóstico para esa misma página, no significa GL/banco/IVA conciliado, y `ledgerReconciled:false` siempre.

Esta validación adicional se ejecuta tras la consulta; no reemplaza sumas SQL ni genera una segunda fuente de verdad. No hay datos persistidos ni asignación de saldos. Tests: `node --test tests/kpi_page_reconciliation_v771.test.mjs`.
