## Truth rules

- Every required gate begins as `NOT_EXECUTED`.
- `PASS` requires attached evidence. Source review alone cannot promote DB/browser/PWA/backup checks.
- `BLOCKED` may carry `blockerKind`, for example `EXTERNAL_PROVIDER`, `PHYSICAL_DEVICE`, or `INFRASTRUCTURE`.
- The candidate SHA and optional baseline SHA are immutable within one manifest.
- The final diff and secret reviews are first-class required evidence.
- `RELEASE_READY` is emitted only when all non-Actions required evidence and release-scope items are `PASS`.

## Temporary GitHub Actions policy

By explicit operational instruction, GitHub Actions is currently represented as:

`NOT VERIFIED / NON-BLOCKING`

The manifest enforces that state and **rejects a fabricated Actions `PASS`**. This exemption affects integration blocking only; it does not convert any unexecuted DB, browser, WhatsApp LAB, security, backup/restore, physical QA or soak evidence into PASS.

When the infrastructure policy changes, update this versioned release policy in a dedicated change rather than silently reinterpreting old manifests.
