# #853 · Transactional job intent foundation (increment 1)

Scope: tenant-bound storage and atomic enqueue/claim/completion/retry primitives. This is **not** a worker, handler registry, notification delivery system, or complete #853 implementation. Source reuse: `NONE`.

- **Producer:** inside the same existing `Prisma.TransactionClient` as the domain write, call `enqueueAsyncJobIntent(tx, ...)`. A standalone transaction/HTTP call after commit can lose the job and is forbidden. `enqueueAsyncJobIntent` now also requires a **trusted** `AsyncJobHandlerRegistry` (merged code-only PR #1070) and checks a canonical JSON copy with the approved per-handler schema **before INSERT**; missing, forged, unversioned or unreviewed registrations fail closed. No handlers are registered or activated by this change. `handlerKey` must be a versioned, explicitly reviewed handler; do not enqueue until that handler has been registered by a subsequent approved implementation.
- **Idempotency:** `(tenantId,effectKey)` is unique at the DB. Same request fingerprint returns the original row; a different fingerprint is rejected with `ASYNC_JOB_IDEMPOTENCY_CONFLICT`. Request identity includes handler, canonical JSON payload, runAt and retry budget. Keep payload minimal, bounded to 16 KiB, without credentials, arbitrary contact details, or sensitive clinical data. This foundational policy does not yet enforce domain-specific payload schemas.
- **Consumer:** a future tenant-bound worker can claim up to 25 due jobs with `FOR UPDATE SKIP LOCKED`, using a 15–900 s lease and retryable-expiration takeover. Every claim has a distinct per-attempt fencing token returned as `leaseOwner` (caller passes it as `leaseToken`), even if a worker process reuses its name. PostgreSQL `clock_timestamp()` rather than the worker clock determines due/expired claims and lease deadlines, retry schedules and audit update times, preventing a skewed or stale caller timestamp from taking over a valid lease. `heartbeatClaimedAsyncJob` renews only a live claim using the unique token and database clock; stale workers cannot revive a lease. It has no automatic scheduler or worker loop. An expired final attempt can be marked `dead` using `quarantineExhaustedAsyncJobLeases`; this helper is not scheduled yet. The worker must execute each handler with durable effect idempotency; a lease by itself cannot guarantee exactly-once external effects. `completeClaimedAsyncJob`, `failClaimedAsyncJob` and `heartbeatClaimedAsyncJob` share strict UUID job-ID and per-claim lease-token validation before the compare-and-set lease guards. Failure writes only an allowlisted safe error code, not raw provider responses. After the standalone safe-failure policy merged in #1084, `failClaimedAsyncJob` now accepts an opaque failure plus `idempotentRetryVerified` and calls `classifyAsyncJobFailure` **before** the SQL update; arbitrary provider errors are terminal and an unverified external effect can never be automatically retried. The flag is a trusted handler assertion, not proof by itself; each future handler must substantiate idempotency with an effect ledger, provider key or CAS.
- **Tenant isolation and bootstrap order:** the additive Prisma migration creates the table with `ENABLE/FORCE ROW LEVEL SECURITY` and **no permissive policies**. The existing #845 canonical sidecar defines `private.contagest_runtime_tenant_id()` and then builds `contagest_runtime_tenant_scope` for PascalCase tables with `tenantId`. Thus freshly migrated data stays unavailable to runtime until the approved #720/#845 role/policy provisioning **runs after** Prisma deploy. Production provisioning must use its authorized runbook; `backend/scripts/runtime-rls-v845.mjs` is an isolated-test harness and must **not** be run against production. Verify `pg_policies` and forced RLS before activating any producer. Workers must bind the tenant in the same transaction; no privileged dispatcher bypass was added.
- **No activation:** `/api/v1/notifications/send` still fails closed with 503 until #854 consent/templates, an approved #853 worker and #772 provider adapters are actually wired. No automatic WhatsApp messages, finance posts, or external API calls are introduced. A read-only `inspectTenantAsyncJobHealth` helper returns tenant-scoped decimal-string counters for queued/retry/running/dead, expired and exhausted leases, and oldest due schedule without exposing payload or error details. No public health endpoint or polling loop is enabled.
