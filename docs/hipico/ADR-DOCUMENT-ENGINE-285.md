# ADR — Document/PDF Intelligence Engine (#285)

## Status
Accepted for stacked implementation. Release remains gated by executable final-SHA evidence.

## Decision
Control Hípico treats every PDF as hostile evidence. The document pipeline owns binary validation, immutable provenance, bounded extraction, classification and operator approval; it never settles money and never converts document text into executable instructions.

The canonical boundary is `/api/v1/hipico/documents*`. Raw PDF bytes remain backend-only in PostgreSQL. Public responses contain metadata, extraction and provenance but never `raw_pdf`.

Native text extraction is implemented through PDF.js. OCR is a fallback only when native text is insufficient and requires the explicit `HIPICO_DOCUMENT_OCR_ENABLED=true` switch plus the runtime OCR dependencies. No shell command, Poppler/Tesseract executable or arbitrary child process is invoked by the production pipeline.

## Authority
Text such as `RESULTADO OFICIAL` is a claim, not authority. `OFFICIAL_RESULT` is permitted only when provenance is `authority=official` and the source channel is present in `HIPICO_OFFICIAL_DOCUMENT_CHANNELS`. Any lower-authority document is downgraded to `RESULT` and keeps `claimedOfficial=true` in extraction evidence.

## Persistence
`hipico_documents` stores SHA-256, bounded metadata, classification, parser version, authority, extraction and the original bytes. `hipico_document_sources` records every source occurrence. Duplicate hash is idempotent; same source-message identity with changed bytes fails closed. Revisions use `supersedes_id` and must remain in the same owner/group scope.

## Security bounds
- MIME route + `%PDF-` magic validation.
- Maximum 10 MiB and 200 pages at ingress.
- Reject JavaScript, EmbeddedFile, Launch/OpenAction and RichMedia markers before parsing.
- Extraction timeout is enforced by `AbortSignal`.
- Extracted text is capped before persistence.
- OCR is capped to 40 pages.
- Operator token is required for document API mutations/reads in this product boundary.
- No raw SQL/shell/admin tool is exposed to document content.

## Dependencies
Runtime extraction is capability-driven. `pdfjs-dist` is required for native extraction. OCR additionally requires `tesseract.js` and `@napi-rs/canvas`. The code reports `not_configured` rather than pretending OCR/native extraction exists when the package installation is unavailable.

The package lock must be generated by the repository package manager and validated with `npm ci`; it must not be hand-authored to manufacture dependency evidence.

## Rollback
Revert the code and additive SQL migration before deployment. Once document rows exist, rollback of storage requires an explicit evidence export/data-migration decision; do not drop tables automatically.
