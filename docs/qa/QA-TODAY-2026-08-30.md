### Physical QA #119

```bash
npm run qa:today:prepare -- --scope=hipico
```

Edita **durante la prueba**, no antes:

`artifacts/qa/hipico-v119/<SHA>/physical-qa.json`

SOURCE no debe recibir escrituras. Usa un harness LAB local/simulado, no una sesión ni grupo de WhatsApp real. Ejecuta la matriz: fresh install, upgrade, background/resume, kill, reboot, permisos, offline/reconnect, dos sesiones simuladas, recuperación, cambio de identidad del perfil, jornadas sintéticas SOURCE→parse→prediction→respuesta simulada, scroll/overlap, batería/memoria, backup/restore y handoff/restart.

Al terminar:

```bash
node scripts/hipico-physical-qa-v119.mjs status
node scripts/hipico-physical-qa-v119.mjs check
```

### Soak #120

El soak final debe durar >=24h. Ejemplo seguro:

```bash
GIT_SHA=$(git rev-parse HEAD) npm --workspace backend run soak:hipico -- \
  --duration-minutes=1440 \
  --source-read-only=PASS \
  --lab-only-write=PASS
```

Los recovery drills requeridos deben ejecutarse realmente y pasarse por sus flags; no marques PASS sólo porque el proceso sobrevivió.

## 4. WhatsApp Production #154 / Promotion #121

El perfil vigente es WhatsApp Messenger normal para un grupo privado de amigos, recreativo y sin dinero real. WhatsApp Business y sus API están excluidos. Las Condiciones de Messenger restringen mensajería automática y usos no personales salvo autorización expresa, por lo que el gate de autoenvío permanece `NO_GO` y #121 debe mantener `shadow`.

QA puede cubrir producto, parsing, respuestas y recuperación mediante harness local y datos sintéticos. No conectarse a grupos reales ni interpretar una prueba simulada como autorización de envío automático.

## 5. Estado final

```bash
npm run qa:today:status -- --scope=all
```

Interpretación obligatoria:

- `PASS`: caso realmente ejecutado y conforme;
- `FAIL`: defecto reproducible;
- `BLOCKED`: dependencia externa/infraestructura impidió ejecutar;
- `NOT_EXECUTED`: aún no ejecutado;
- nunca convertir BLOCKED/NOT_EXECUTED en PASS.
